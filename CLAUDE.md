# Правила проекта для Claude

Браузерное расширение «Счётчик писем для Яндекс Почты» (Chrome 121+, Firefox 142+, Manifest V3): счётчик непрочитанных писем и уведомления о новых письмах. Устройство кода, команды и порядок выпуска описаны в [CONTRIBUTING.md](CONTRIBUTING.md) — прочитай его перед работой.

## Авторство

Все изменения в репозитории делаются от имени владельца проекта.

- Перед первым коммитом в сеансе:
  ```bash
  git config user.name "Ogurtsov-D"
  git config user.email "78870757+Ogurtsov-D@users.noreply.github.com"
  ```
- Не добавляй в сообщения коммитов строки `Co-Authored-By: Claude …` и `Claude-Session: …`.
- Не добавляй в описания PR строку «Generated with Claude Code» и ссылку на сеанс.

## Язык

Документация, сообщения коммитов, описания PR и комментарии в коде — на русском; у README есть английская версия `README.en.md`. Интерфейс расширения — на 19 языках: русский и английский — основные, остальные переводы ещё не проверены носителями языка (список в CONTRIBUTING.md, раздел «Переводы»). Обращение к пользователю в документации — на «вы».

## Перед коммитом

- `npm run check` должен проходить: тесты, ESLint, Prettier, `web-ext lint`.
- Новое поведение — с тестом в `tests/`. Тесты не отключать и не ослаблять ради зелёной проверки.
- Перед релизом с заметными изменениями — сквозные проверки `npm run e2e` и `npm run e2e:firefox` (как запустить — CONTRIBUTING.md).
- Изменения, заметные пользователю, — в раздел `## [Не выпущено]` в начале `CHANGELOG.md`.
- Тексты интерфейса — только через `t()` / `plural()` из `src/i18n.js` и во всех файлах `_locales/*/messages.json` (кроме регионального `en_GB`); формы числа — по `Intl.PluralRules` языка.
- Изменились тексты меню, бейджа или уведомлений — обнови `docs/mockup.html`, `docs/mockup-en.html` и пересоздай скриншоты.
- Изменился README — обнови и `README.en.md`.

## Ограничения расширения

Это обещано пользователям в README, `PRIVACY.md` и `SECURITY.md` — не нарушай без явного решения владельца:

- сетевые запросы — только к почте Яндекса на адресе, выбранном пользователем (`MAIL_HOSTS` в `src/config.js`; по умолчанию `mail.yandex.ru`, остальные — через `optional_host_permissions`);
- никаких действий в почте: не отмечать прочитанным, не удалять, не отправлять;
- никакой аналитики, трекеров, сторонних библиотек в коде расширения (`src/` без зависимостей);
- новые разрешения в `manifest.json` — только с обоснованием в README (таблица разрешений) и в `PRIVACY.md`.

## Рабочий процесс

- Изменения — через ветку и PR в `main`; вливать после зелёного CI.
- Версия меняется одновременно в `manifest.json`, `package.json` и `CHANGELOG.md` (это проверяет `tests/manifest.test.js`). Каждую версию выпускают один раз: Mozilla не подписывает её повторно.
- Релиз создаёт владелец на странице Releases (тег `v<версия>`); остальное делает `.github/workflows/release.yml`.

## Что ещё не проверено на настоящей почте

- Формат адреса письма для перехода из уведомления: `#/message/<id>` (`src/parser.js`, `messageHash`) — сверен с расширением pulsar, а не с нашим ящиком. Для тредов адреса нет, открывается почта. Если владелец сообщит, что открывается не то письмо, исправлять там.
- Образцы страниц в `tests/fixtures/` воссозданы по разметке, на которую опираются другие расширения (см. `tests/fixtures/README.md`), а не сохранены с настоящей почты.
- Другие адреса почты (`mail.yandex.com`, `.by`, `.kz`, `.com.tr`, `mail.360.yandex.ru`): есть ли там API счётчиков и lite-версия по тем же путям — не проверено; если API нет, работает запасной подсчёт по lite-версии.
- Несколько аккаунтов: логин для подписи берётся из шапки lite-версии (`b-head-user` → `b-user`, `parseAccountLogin` в `src/parser.js`) — разметка шапки не сверена, при неудаче аккаунт подписан номером. Письмо другого аккаунта открывается по адресу `?uid=<uid>#/message/<id>`, вкладка аккаунта ищется по `?uid=` в её адресе — не проверено, сохраняет ли Яндекс `?uid=` в адресе вкладки.
- Разметка lite-версии на компьютере (не телефоне) — владелец пришлёт исходник страницы; по ней сверить `src/parser.js` и `tests/fixtures/`.

Проверено владельцем: `GET /api/v2/bar/counters?silent` отвечает `{"counters":{"fresh":N,"unread":N}}`, без входа — 401. С `&multi` — массив `[{"uid":"…","data":{"counters":{…}}}]` по всем аккаунтам, числа совпадают с ящиками; `/lite/inbox?uid=<uid>` открывает «Входящие» нужного аккаунта. `unread` — непрочитанные во всех папках, кроме «Спама»; `fresh` — пришедшие после последнего захода в почту, обнуляется при заходе. `/api/v2/bar/accounts` отдаёт личные данные — не использовать.
